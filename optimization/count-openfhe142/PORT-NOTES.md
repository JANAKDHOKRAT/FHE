# Port scope and diagnosis

Original1.3.1 code is preserved at optimization/count/. This separate copy adds1.4.2 to its tested-version candidate list; runtime loaded-library checks remain intact. Existing Count circuit, native-key mode and all cryptographic profile choices are unchanged. New test count142.rs pins actual1.4.2 libraries, full Q/QP arrays, ring32768, depth18, digits7, wire6176895B, plaintext boundary cases and batch limit32.

The prior1.4.2 noise-test failure was reproducible with the two key_noise_gap cases running concurrently; the silent case passed in isolation. The wrapper explicitly requires context creation and key installation not to race other operations because of process-global OpenFHE tables. Two copied test modules lacked their existing peers' serialization guards: key_noise_gap.rs and crs_ceremony.rs. Added a per-test-program mutex around each whole test. No cryptographic operation, parameter, expected value, bound or assertion was removed or weakened. Rebuilt wrapper tests pass with a two-thread runner, demonstrating the guards, not merely a single-thread command, prevent the observed interaction. A stale pre-rebuild regression probe was retained under threshold-pair-before-rebuild.log and was not mistaken for the rebuilt result.

The original default Cargo protocol qualification began serially. Its55 unit tests and batch_noise stress test completed successfully. The partial next program was intentionally interrupted and rescheduled in full, along with all remaining integration test programs, as independent processes (three workers, one test thread each). Global tables are process-local; no assertions or test cases are skipped by this scheduling change. The pre-existing ignored ceremony_sweep measurement remains ignored and must be reported separately. The final runner manifest is the compiler's actual test-artifact list, not guessed executable paths.

This is a core Count compatibility port under the existing trust model, not an implementation of the full DAP service or a port of count-auth. It does not resolve arbitrary-ciphertext security, circuit privacy, or the separate independent parameter-screening findings. Calls that create contexts or mutate installed keys still require serialization against evaluation, as in the original API contract. Do not claim general concurrent-initialization safety or production certification.

Comparison adapters use1.4.2 for both sides, original STD128/GINX Boolean parameters, and the existing p65537 BGV Count profile. They preserve algorithms and expose matched timing phases, key reuse and key/context loading. Original professor source and1.4.2 build remain untouched. See comparison/PROTOCOL.md; no benchmark result is accepted while qualification jobs are active.
